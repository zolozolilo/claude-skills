# Экономия токенов

Каждый мой ответ и каждый шаг агента заново читают весь контекст. Дорого не то, что сделано, а то, что сделано зря или дважды.

## Перед каждым действием — три вопроса

1. **Это продвигает дело прямо сейчас?** Нет — не делаю (отчёт «на всякий случай», лишний документ, повторная проверка).
2. **Это уже сделано / решено?** Да — ссылаюсь, не повторяю.
3. **Можно дешевле?** Скрипт вместо агента, Grep/offset вместо чтения файла, Sonnet/Haiku вместо Opus, один вызов вместо пяти.

## Правила

- **Ответ — 3–6 строк.** Итог, цифры, что нужно от пользователя. Таблица — только по просьбе. Не пересказываю сказанное.
- **Вопрос — только когда без ответа нельзя идти дальше.** Разумное по умолчанию решаю сам и называю одной строкой.
- **Решение принято → сразу задания исполнителям.** Документы (план, спецификация) — короткие (≤ 300 строк), после дела или вместе с ним, не вместо.
- **Направление сменилось → остановить агентов с устаревшей работой**, не ждать их отчёта.
- **Модель — минимально достаточная:** механика, скрипты, копирование, тексты — Sonnet; поиск и чтение логов — Haiku; Opus — только сложная логика, архитектура, ревью. Запустил дороже, чем надо, — остановить и перезапустить дешевле, пока агент не ушёл далеко.
- **Агенты — по скиллу `budgeting-agent-tokens`:** одна короткая задача, ≤ 3 одновременно, свежий агент при контексте > 300 тыс., тесты своего участка.
- **Файлы и логи:** Grep, offset/limit, хвост; большие — в файл, читаю итог.
- **Ожидание — одной командой в фоне**, без опросов.
- **Записи (память, заметки) — одной правкой в конце этапа**, не после каждого шага.

## Красные флаги

| Мысль | На деле |
|---|---|
| «Распишу подробно, чтобы было понятно» | Длинный ответ перечитывается каждым следующим шагом |
| «Сначала доведу план до идеала» | План на 5 700 строк прочитали три агента — десятки миллионов токенов |
| «Спрошу на всякий случай» | Вопрос = ещё круг; решай сам, если можно откатить |
| «Агент почти закончил, пусть доделает» | Если результат больше не нужен — остановить сейчас |
