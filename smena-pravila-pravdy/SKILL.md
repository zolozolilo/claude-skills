# Смена правила правды

## Суть
Когда меняется источник правды или правило выдачи, дыры сидят в боковых путях, которых автор не коснулся. Тесты автора проверяют сделанное, а не забытое. До выкладки — весь круг ниже, по порядку.

## Круг до выкладки — у каждого пункта доказательство
1. **Все пути.** Таблица «путь → тест»: все места, которые выдают, возвращают и пишут. По КАЖДОМУ имени, которое трогает правило (поле, метод, ключ JSON, модуль в скрипте выкладки):
   `python ~/.claude/skills/smena-pravila-pravdy/kto_pishet.py <имя> [<имя2>…] -k <репо1> -k <репо2>` (`--json` — агенту)
   - Корни — все места, где имя живёт: бэкенд, фронт, скрипты выкладки, копии и заплатки. Варианты snake/camel/Pascal ищет сам; общее имя (`size`, `run`) — `--tochno`.
   - Каждая строка ПИШЕТ и вызов вне тестов — свой тест; ⚠НЕДОСТИЖИМ (код под `return`) — разобрать до правки; «НИЧЕГО НЕ НАЙДЕНО» — не ура, а проверить имя и корни.
   - Чего скрипт не видит, дописать руками: `getattr(o, имя)`, `obj[переменная]`, HTTP из репозитория вне `-k`, код только на сервере. «Динамический доступ» в выводе — открыть строки рядом с правкой; «⚠ Корень один» — добавить корни. Меняется возвращаемое метода — второй круг по его вызывающим.
   - Вывод скрипта — дословно в задание агенту и ревизору. Для пути записи: не вернёт ли он то, что пользователь уже унёс?
   - Боковые пути, которые поиск по имени пропускает, пройти отдельно: выдача и возврат, запись файлов, откат, замена, починка при запуске, чистка, приказы с сервера. Путь без теста — дописать тест.
   - Список-реестр (sections.js, скрипт выкладки, ночной скрипт, ворота): `python ~/.claude/skills/smena-pravila-pravdy/reestr_polon.py --papka <папка> --shablon "<маска>" --reestr <файл> [--reestr …]` — каждый файл назван в каждом реестре.
   - Чини класс, не экземпляр: все ключи, все источники правила. Условие переносишь между хранилищами — сперва проверь, что оно верно в новом.
   - Новый триггер («по событию», хук, сторож): сначала увидеть событие в реальном журнале — как оно приходит (файл/cron/запрос; текст/подпись/пусто); после выкладки — убедиться, что событие замечено (скилл `nikomu-ne-ver`).
2. **Ревизор — не автор.** Свежий агент, только чтение, задание «найди путь, где новое правило нарушается». Каждая находка — сначала падающий тест, потом починка.
3. **Склейка.** Параллельные ветки — ревизор, сценарии и мутации идут по СКЛЕЕННОМУ результату после последнего слияния.
4. **День пользователя.** Сценарии реального дня: назначил, унёс, откатил, файл занят другой программой, папки нет, перезапуск. В конце каждого сценария — общий закон (ничего не выдано дважды, ничего не пропало).
   - Массовый перенос или новое правило расчёта: сухой прогон — список затронутого показать ДО выкладки; правило — на реальной истории, не рассуждением; потом граничные (минус, 0, «неизвестно»).
   - Одно число в двух местах (экран и файл): оба из одного расчёта, тест «равны».
5. **Мутации.** Сломать каждую защиту (вырезку, сверку, стоп выгрузки) — тест обязан покраснеть. Не покраснел — защиты тестом нет. Автоматом: StrykerJS `thresholds.break`, Stryker.NET `--break-at 80`, mutmut; без инструмента — ручные мутанты (строку защиты заменить → прогон → красный).
6. **Кнопка → текст человеку.** Для каждого предупреждения: что пользователь увидит, не затрёт ли его следующий шаг, не горит ли «зелёное» рядом с остановкой.
   - CSS для одного раздела — только внутри его контейнера: `python ~/.claude/skills/smena-pravila-pravdy/css_bez_prefiksa.py --diff <база> --repo <репо> --prefiks .<раздел>`; ⚠ — селектор действует на всю страницу. Потом соседние разделы и три ширины — глазами.
7. **Живой запуск** в песочнице, снимки экрана. Никогда — свежая сборка на боевых данных.
8. **Инструкция людям** — только после п. 7, по снимкам.
9. **Выкладка** — отдельной командой после полного зелёного прогона, увиденного глазами. Тесты и выкладка в одной строке через «;» запрещены: PowerShell идёт дальше после красного. Зелёный = прочитанный сегодня вывод на склейке: failed 0, skipped 0, exit 0; числа итога — в сообщение о выкладке.

## Когда горит
Люди стоят — сужается выкладка, не круг: только главное правило, без новых кнопок из параллельной ветки (`git revert -m 1 <слияние>`). П. 1 скриптом — секунды, не пропускается никогда. Пункты 2, 4–6 — свежими агентами параллельно; сразу назвать срок по самому долгому.
