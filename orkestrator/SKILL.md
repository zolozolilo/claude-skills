# Оркестратор — я мозг, агенты — руки

Я думаю и решаю: дерево задач, задания, вердикты, согласия, ответ пользователю. Код, прогоны, сверку и разбор делают агенты подходящей модели. Мой контекст дорогой и общий для всей сессии — в нём должны жить решения, а не файлы и логи.

## Роли и модели

| Роль | Модель | Делает | Не делает |
|---|---|---|---|
| **Мозг** (я) | основная | дерево, решения, задания, вердикт, вопросы и вехи пользователю | не пишет код, не гоняет долгие прогоны |
| **Строитель** | дешёвая (Sonnet) — механика по точному заданию: правки, слияние, прогоны; в Agent явно `model: sonnet`, `effort: low`, иначе агенты по умолчанию уходят на дорогую модель. Сильная (Opus) — сложная логика и архитектура | RED → правка → прогоны → SHA и записка | не расширяет объём; согласие — не его |
| **Сверщик** | самая дешёвая (Haiku) | после сдачи: состав изменений против эталона, SHA, числа из логов против отчёта строителя; ≤8 строк | не судит качество |
| **Критик** | отдельный агент-ревьюер (если нет — свежий агент с ролью «независимый ревьюер по диффу») | вердикт ПРИНЯТЬ / ВЕРНУТЬ по диффу, свои зонды, воспроизведение | не правит |
| **Разбор** | Sonnet, только чтение | спорные места: кто прав, на каком основании; вывод в файл | не правит и не гоняет тяжёлое |

## Цикл одного листа

1. **Задание:** цель + рамки + «готово, когда»; RED (тест, падающий на старом коде) до кода; точные пути и имена (снапшоты, SHA); «к ~200 тыс. контекста — сдай по записке».
2. **Сдача строителя** → сверщик сверяет его числа с файлами. Расхождение — стоп, разбираюсь.
3. **Снапшот** `<файл>.кандидат-<sha8>` до вердикта.
4. **Свежий критик.** Находку «ВЕРНУТЬ» воспроизводит сверщик или одна моя команда — до возврата строителю.
5. **Вердикт → запись** (журнал, точка возобновления) → следующий лист.

Независимые листы — параллельно в разных копиях или файлах (`octopus`); тяжёлые прогоны в одной папке — строго по одному.

## Правила мозга (каждое — оплаченная ошибка)

- **Не делаю руками.** Хочется «быстро поправить сам» или «прогнать проверку сам» — значит, это лист для дешёвой модели. Моё — одна короткая команда сверки.
- **Отчёт агента ≠ факт.** Числа и вердикты — только после сверки (`nikomu-ne-ver`). Оборванный отчёт критика, начинающийся с «Приёмка до чтения кода…», — это его план, не результат.
- **Точные имена в задании.** Одно неверное имя снапшота — и проверка уходит впустую (критику дали снапшот теста вместо кода).
- **Объём согласия.** Исправления — только с согласия пользователя и в названных границах. Если работа тянет больше (правки в чужих файлах, закрепления, запрещённые скрипты) — снова спросить ДО старта.
- **Второй источник до необратимого.** Диагноз чужой системы перед ресетом, удалением или откатом — с независимой стороны, не только со своего компьютера.
- **Бюджет агентов.** К 200 тыс. — сдать по записке; выше 300 тыс. — сразу «сдай после фона, новых шагов не начинай», продолжает свежий (`budgeting-agent-tokens`).
- **Сломалась трасса агентов** (обрывы прокси, пустые ответы) — не воскрешать по кругу: после 2–3 обрывов ищу причину маршрута (настройки env, модель), меняю трассу, говорю пользователю.
- **Пользователю — вехи, коротко.** Вопросы — пачкой, рекомендация первой; развилки по умолчанию — «как сейчас». «Стоп» — остановить всех агентов, сделанное не откатывать, записать точку возобновления.
- **Решения записываю сразу** — в точку возобновления: следующий мозг (после сжатия или новой сессии) должен продолжить без пересказа.

## Красные флаги

| Мысль | На деле |
|---|---|
| «Быстрее сам поправлю» | Мозг не пишет код — задание дешёвой модели |
| «Сам перепроверю всё целиком» | Сверщик; мне — его 8 строк |
| «Агент написал 62 passed» | До слов пользователю — сверка |
| «Возобновлю упавшего ещё раз» | Третий обрыв подряд — проблема трассы, не агента |
| «Сильная модель на всё» | Механика — Sonnet, сверка — Haiku, сильная — где думать |
| «Объём тот же» | Задеты чужие файлы — объём шире, спросить |
| «Подожду агента, проверяя каждые 2 минуты» | Уведомление придёт само; ждать молча |

## Связанные
